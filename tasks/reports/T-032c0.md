## 2. API del shim (`apps/web/src/fx/showdown/`)
Fiel a la API que usa la mayoría de `battle-animations-moves.ts`: `scene.showEffect(img, start,
end, transition?, 'fade'|'explode')`, `scene.backgroundEffect(color, dur, opacity?, delay?)`,
`actor.anim(end, transition?)` (defaults hogar + time 500), `actor.delay(ms)`, `leftof/behind`,
easings PS (swing/accel/decel/ballistic*/quad*, mapeo de posT()) y pos() base 210/245 con
z→escala 1.5−0.5·z/200. Diferencia deliberada: PS anima `left/top/width/height` (layout); el
shim anima **solo `transform`+`opacity`** (translate3d+scale, WAAPI, ~14 keyframes muestreados).
Host abstracto (`FxHost`/`FxElement`) ⇒ sin jsdom: tests con elementos simulados (patrón para
T-032c2); `webHost.ts` es el adaptador DOM. `speed` divide duraciones; `reducedMotion`/skip ⇒
destello de 150 ms en el defensor; `AbortSignal` cancela; presupuesto ≤ 40 elementos (MAX_FX).

## 3. Demo `/dev/fx` (AC-1)
Escena 640×360 escalada (ResizeObserver), sprites reales frente/espalda de `sprites.json`
(fallback tarjeta con nombre), selects con los 5 iniciales, botón por movimiento (Burbuja,
Lanzallamas, Arañazo, Látigo cepa, Rayo, Doble bofetón), velocidad 1×/2×/saltar,
reduced-motion, pico de elementos FX y sonda de FPS + peor pausa. Chunk lazy (`import()`).
Los 6 puertos son fieles al código real (bubble=bubblebeam, vinewhip=powerwhip+contactattack,
scratch=slashattack, doubleslap=xattack, thunderbolt=3 rayos+fondo).

## 4. Medición y decisión DOM vs canvas (paso 4)
- Presupuesto estático (verificado por test): solo transform/opacity (compositor), ≤ 40 y en la
  práctica 3-5 elementos por movimiento, duraciones 100-1100 ms a 1×.
- Sonda de FPS incluida en la demo para correr en un móvil medio (muestra fps promedio y peor
  pausa); Showdown mismo usa esta técnica DOM en móviles. **Decisión: DOM** (WAAPI), sin
  `pixi.js` (ADR-6 se mantiene). Medición en dispositivo real: la hace el dueño en GS.

## 5. Dificultad por movimiento (fácil/medio/difícil) y estimación
| Movimiento (id) | Tipo en PS | Dificultad |
|---|---|---|
| Burbuja (bubble/bubblebeam) | 4 proyectiles decel+explode | fácil |
| Lanzallamas (flamethrower) | 4 proyectiles decel+explode | fácil |
| Rayo (thunderbolt) | fondo + 3 imágenes con yscale | fácil |
| Arañazo (scratch/slashattack) | coreografía de sprites (embestida ballistic) | medio |
| Doble bofetón (doubleslap/xattack) | doble embestida + sacudida + 2 wisp | medio |
| Látigo cepa (vinewhip/powerwhip) | 2 bolas + 3 hojas + contacto | medio |
| (movimiento sin portear) | respaldo: arquetipo propio (T-032c1) | n/a |
Regla general: proyectil/beam/imagen = fácil; coreografía de sprites = medio; pantalla completa
o muchísimas partículas (surf, blizzard, earthquake) = difícil. Estimación T-032c2: fácil
~20-30 min, medio ~30-60 min, difícil 1-2 h + revisión visual ⇒ lote inicial (iniciales +
mazos MVP, ~40-60 movimientos) ≈ 2-4 días.
