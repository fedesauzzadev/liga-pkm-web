# Plan T-006 — Barreras de calidad

Spec: `specs/SPEC-A-foundations.md` §T-006 · Deps: T-001 (DONE), T-004 (REVIEW) · Modelo: M

## Alcance
Convertir las reglas de `docs/ENGINEERING-STANDARDS.md` en bloqueos automáticos dentro de
`pnpm verify`: tsconfig estricto, ESLint duro, dependency-cruiser, size-limit, ids con marca,
registro de invariantes + Logger en el motor, reporte de bug en la web, `pnpm bench` con
presupuestos y `verify:selftest` que demuestra que cada barrera bloquea.

## ACs (SPEC-A §T-006)
- AC-1 tsconfig base: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`,
  `noImplicitOverride`, `noFallthroughCasesInSwitch`.
- AC-2 ESLint: en `packages/engine` prohíbe `Math.random`, `Date.now`, `performance.now`,
  `console` y globals de DOM; en todo el repo prohíbe `any`, `@ts-ignore`,
  `@ts-expect-error` sin descripción; exige `switch` exhaustivos.
- AC-3 dependency-cruiser: `web → engine → content`, sin ciclos, `engine` sin react/DOM-libs.
- AC-4 size-limit: JS inicial ≤ 200 KB gzip; `pnpm verify` falla si se supera.
- AC-5 Ids con marca (`CardId`, `NodeId`, `PkmUid`, `PlayerId`) en `@liga/content` con
  parseo Zod; mezclar dos tipos de id no compila.
- AC-6 `registerInvariant(name, fn)` + `assertInvariants(state)`; el reductor las ejecuta tras
  cada comando cuando `NODE_ENV !== 'production'`.
- AC-7 `Logger` inyectado en `ctx` (`NoopLogger` por defecto); registra comando, eventos y dados.
- AC-8 `exportBugReport()` + descarga JSON; `ErrorBoundary` en el shell web; panel mínimo con `?debug=1`.
- AC-9 `pnpm bench` con `perf-budget.json` (§3); falla si un benchmark supera su presupuesto.
- AC-10 `verify:selftest`: una sonda rota por regla (AC-2, AC-3, AC-4) demuestra que verify falla.

## Diseño
- `tsconfig.base.json` — agregar `exactOptionalPropertyTypes` (el resto ya está).
- `eslint.config.mjs` — repo: `no-explicit-any`, `ban-ts-comment` (expect-error con descripción),
  `switch-exhaustiveness-check` (type-aware, `project: true`, default defensivo permitido);
  engine: `no-console`, `no-restricted-properties` (Math.random/Date.now/performance.now),
  `no-restricted-globals` (lista DOM + Date/performance).
- `.dependency-cruiser.cjs` + devDep `dependency-cruiser` + script `deps:check`. Reglas:
  `no-circular`, `engine-sin-ui` (engine → web/react/react-dom/zustand/motion),
  `content-hoja` (content → engine/web), `nadie-importa-web`.
- `size-limit` + `@size-limit/preset-small-lib`; entrada `apps/web/dist/assets/*.js` @ 200 KB;
  script `size`; `verify` lo corre tras `build`.
- `packages/content/src/ids.ts` — marcas Zod (`z.string().min(1).brand()`) + `parseCardId` etc.
- `packages/engine/src/invariants.ts` — `Invariant`, `registerInvariant`, `assertInvariants`,
  `InvariantError` (código `INVARIANT_VIOLATED`), flag habilitado por defecto
  (`NODE_ENV !== 'production'` leído vía `globalThis`, sin tipos de Node) y
  `setInvariantChecksEnabled` para la UI. Registra las invariantes del estado actual
  (versión ≥ 1, turno entero ≥ 0, dado con cara 1-6). `applyCommand` las ejecuta tras cada
  comando exitoso.
- `packages/engine/src/logger.ts` — `Logger { command, events, die }`, `NoopLogger`,
  `createMemoryLogger` (tests y futuro panel). `Ctx.log?: Logger` con fallback Noop.
- `apps/web/src/debug/` — `session.ts` (última semilla + log de comandos; T-030 lo alimenta),
  `bugReport.ts` (`buildBugReport` puro + `exportBugReport` con descarga y guard SSR),
  `ErrorBoundary.tsx` (Reintentar / Exportar reporte), `DebugPanel.tsx` (`?debug=1`, mínimo).
  Textos en `i18n/es.ts`; estilos en `debug.module.css`; `main.tsx` envuelve con ErrorBoundary.
- `perf-budget.json` + `tools/bench.ts` + script `bench`: mediana de muestras; falla si supera
  presupuesto o si un benchmark no tiene presupuesto. Hoy: `content:load-validate` ≤ 300 ms.
  T-011/T-020/T-021 agregan movimiento/turno de combate.
- `tools/verify-selftest.mjs` + script `verify:selftest`: sondas temporales
  (Math.random+console en engine → eslint; import react en engine → depcruise;
  `size-limit --limit "1 B"` → falla). Cada sonda debe FALLAR; limpia todo al final.
- `verify` = typecheck && lint && test && content:validate && build && deps:check && size && bench.
- Tests: `tests/t006-quality.test.ts` — un test por AC (sondas tipo AC-2 de T-001);
  property test con `fast-check` (secuencias aleatorias de comandos legales no violan
  invariantes y `replay` reproduce; estándar §2).

## Fuera de alcance
Panel de debug completo con estado/eventos y conexión real del session recorder (T-030),
invariantes de cartas/equipo (T-010), benchmarks de combate (T-011/T-020/T-021),
guardado/migraciones (T-034).
