# Plan T-010 — Estado inicial + Setup (SPEC-B)

Spec: `specs/SPEC-B-board-turns.md` §T-010 · Deps: G0 · Modelo: M

## ACs (de la spec)
- **AC-1** `newGame({seed, starterDeck, ruleset})` crea 1 jugador en `paleta` con el inicial correspondiente (Bulbasaur/Charmander/Squirtle/Machop/Abra) + 1 elemento de su tipo equipado, 2 comodines, 5 pokebolas, 0 medallas, `cameFrom=null`.
- **AC-2** Si la carta del inicial no existe en el contenido ⇒ error claro (`EngineError`), sin crash.
- **AC-3** Mazos barajados con el RNG (misma semilla ⇒ mismo orden); el inicial se saca del mazo.
- **AC-4** `GameState` serializable (`JSON.parse(JSON.stringify(s))` ≡ `s`).

## Diseño
- `packages/engine/src/setup.ts` (nuevo): `newGame(options, content)` → `Result<CommandOk, EngineError>`.
  - Tabla `STARTERS` deck→carta (RULES §1 p.6-7); el elemento sale de la carta (`card.element`).
  - Nodo inicial: primer nodo `type:'start'` del tablero (dato, no hardcode).
  - Fisher-Yates con `rng.int(n)` nueva primitiva de `Rng` (única fuente de azar; mismo stream que `d6` ⇒ replay determinista).
  - Emite evento `GameStarted`; corre `assertInvariants`.
- `state.ts`: `GameState` gana `ruleset`, `players`, `activePlayerId`, `decks` (pilas por `DeckKey`, cima = índice 0). Tipos `PlayerState`, `PkmInstance`, `ElementCard`, `ItemBag`, `DeckStacks` (SDD §4). `createInitialState()` queda pre-setup (`players: []`, `ruleset: null`).
- `errors.ts`: código `INVALID_SETUP`. `events.ts`: evento `GameStarted`.
- `invariants.ts`: invariantes de T-010 (1 jugador + activo, posición/cameFrom coherentes, equipo ≤ teamLimit, uids únicos, valores ≥ 0, pilas de mazos presentes).
- `content/decks.json` (nuevo, `devOnly`, D-14): mazos de desarrollo con las cartas ya ingresadas + cartas de elemento; necesario para barajar (AC-3). T-044 lo regenera.
- Tests: `tests/t010-setup.test.ts` (un test por AC).

## Fuera de alcance
Máquina de turnos/movimiento (T-011), robo de casilleros (T-012), equipamiento como comando (T-013), `PkmStatus` (T-020).
